# Launch Playbook（发布手册）

发布物料参考库：发布类型、发布策略、灰度放量、回滚、监控基线、阶段 checklist 与风险管理。

`feature-launch` skill 在编排发布、或用户需要某类发布物料（灰度计划、回滚阈值、上线监控、checklist）时，read 本文件。

---

## 发布类型与准备周期

按改动性质先定类型，再据此留足准备时间：

| 类型 | 说明 | 准备时间 | 风险级别 |
|:-----|:-----|:---------|:---------|
| **Hotfix** | 紧急生产修复 | 数小时 | 高 |
| **Patch** | 仅缺陷修复 | 数天 | 低 |
| **Minor** | 新功能、向后兼容 | 1–2 周 | 中 |
| **Major** | 破坏性变更、重大功能 | 1–2 月 | 高 |

---

## 发布策略（选一）

| 策略 | 何时用 | 优点 | 缺点 |
|:---|:---|:---|:---|
| **Big Bang** | 小改动、低风险 | 简单、信息清晰 | 风险高、回滚困难 |
| **Phased Rollout** | 大功能、高风险 | 可控、早期学习 | 完整上线时间长 |
| **Feature Flag** | 非常风险、复杂 | 瞬间回滚 | 基础设施复杂 |
| **Beta Release** | 需验证、反馈 | 早期获得反馈 | 信息泄露、支持负担 |

### 灰度放量计划（Phased Rollout / Feature Flag）

采用 Phased Rollout 或 Feature Flag 时，按阶段放量，每阶段设观察期与放量条件：

| 阶段 | 范围 | 观察期 | 放量条件 | 状态 |
|:-----|:-----|:-------|:---------|:-----|
| 1 | 内部用户 / 白名单 | 1 天 | 无 P0 问题、核心指标无异常 | ⏳ |
| 2 | 5%–10% 目标用户 | 1–3 天 | 错误率低于阈值、无集中负面反馈 | ⏳ |
| 3 | 50% | 2–3 天 | 指标稳定 | ⏳ |
| 4 | 100% 全量 | — | — | ⏳ |

### 回滚计划

| 触发条件 | 动作 | 负责人 |
|:---------|:-----|:-------|
| 发现关键 bug | 回滚到上一版本 / 关闭 feature flag | DevOps |
| 错误率超阈值（如 > 5%） | 回滚并排查 | DevOps |
| 性能劣化 | 回滚或扩容 | DevOps |

### 上线后 24 小时监控基线

| 指标 | 目标 | 告警阈值 | 负责人 |
|:-----|:-----|:---------|:-------|
| 错误率 | < 0.5% | > 1% | 工程 |
| 延迟 (p95) | < 500ms | > 1s | 工程 |
| 核心转化 | 不低于基线 | 下跌 > 10% | PM |
| 支持工单 | 正常水位 | > 2 倍基线 | 支持 |

## 发布阶段 Checklist

### 阶段 1：设计定稿（T-4 to T-3 周）

- [ ] PRD 包括所有完整章节
- [ ] 成功指标定义且可测量
- [ ] 边界情况已识别
- [ ] 原型已创建并审查
- [ ] 用户测试完成（如适用）

**决策点**：
- 功能范围确认？
- 时间线现实吗？
- 资源可用吗？

**产出**：准备评审的 PRD + 已验证的原型

### 阶段 2：准备（T-3 to T-1 周）

**PRD 预审（prd-gen 尾门）**：
1. 提前 48 小时分发 PRD 和原型
2. 走查需求
3. 讨论关注点和边界情况
4. 记录决策
5. 获得签字

**发布计划**：
1. 分解为任务
2. 分配负责人和估算
3. 识别依赖
4. 规划风险
5. 建立状态报告

- [ ] 干系人受邀参加预审
- [ ] 发布计划包含任务和负责人
- [ ] 风险登记册已创建
- [ ] 沟通计划已准备

**产出**：已批准的需求 + 发布计划

### 阶段 3：发布（T-1 周 to T+1 天）

**发布前 Checklist（T-7 to T-1 天）**：

工程：
- [ ] 代码完成并审查，测试通过（unit / integration / e2e）
- [ ] 无未解决的关键 bug；性能测试与安全审查完成
- [ ] 数据库迁移与回滚方案已准备

质量：
- [ ] QA 测试完成，验收标准全部满足
- [ ] 边界情况、兼容性、无障碍已验证

产品：
- [ ] PRD 需求逐条验证，成功指标与埋点已就绪
- [ ] 功能开关（feature flag）已配置（如采用）

文档与沟通：
- [ ] 发布说明已起草，用户 / API 文档已更新
- [ ] 公告与应用内通知已准备
- [ ] 支持团队已简报，销售 / 客服与干系人已同步

合规（如适用）：
- [ ] 隐私与合规审查完成

**发布当天（T-day）**：
- [ ] 部署到预发布，冒烟测试
- [ ] 部署到生产
- [ ] 生产环境冒烟测试
- [ ] 启用功能（或按灰度放量计划逐步放量）
- [ ] 密切监控指标（对照上线后 24 小时监控基线）
- [ ] 准备回滚（对照回滚计划）

**发布后（T+1 天）**：
- [ ] 验证所有系统
- [ ] 发送公告
- [ ] 监控支持渠道
- [ ] 检查指标

**产出**：功能上线且稳定

### 阶段 4：验证（T+1 to T+14 天）

**即时（T+1 to T+7 天）**：
- 监控错误率和性能
- 跟踪采用指标
- 快速响应问题
- 收集初始反馈

**分析（T+7 to T+14 天）**：
- 对比成功指标
- 分析用户反馈
- 识别改进点
- 记录学习

- [ ] 复盘完成（效果分析 + 迭代建议）
- [ ] 反馈已综合
- [ ] 成功/失败已确定
- [ ] 后续步骤已识别

**产出**：复盘报告 + 建议

## 风险管理

常见发布风险和缓解措施：

| Risk | Probability | Impact | Mitigation |
|:-----|:------------|:-------|:-----------|
| Critical bug | Medium | High | 彻底 QA、回滚计划 |
| Low adoption | High | High | 内部测试、营销推动 |
| Performance issues | Low | High | 负载测试、渐进发布 |
| Negative feedback | Medium | Medium | Beta 测试、支持准备 |
| Scope creep | Medium | Medium | 严格变更流程 |
